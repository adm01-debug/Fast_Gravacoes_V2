# ADR 0004 — pt-BR é o idioma do produto; en-US/es-ES são stubs

- **Status:** aceito — 2026-10-01
- **Contexto:** a app é operada exclusivamente por falantes de português
  (chão de fábrica no ES). Os locales `en-US.json` e `es-ES.json` existiam
  com cobertura parcial e strings caindo para fallback — meio-termo que dava
  a ilusão de produto trilíngue sem manutenção real.
- **Decisão:** **pt-BR é o idioma oficial** — novas strings de UI são
  escritas em português. `en-US`/`es-ES` ficam como stubs mínimos
  (fallback funcional para a infra i18next), sem promessa de cobertura.
  Revisitar só se houver caso de uso real de outro idioma; aí a decisão
  vira investimento em tradução completa com dono, não dívida silenciosa.
- **Consequências:** PRs não precisam traduzir para en/es; a suite de testes
  valida pt-BR; remover os stubs um dia é seguro porque ninguém depende deles.
